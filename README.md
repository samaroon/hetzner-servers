# hetzner-dev-servers

> **GitHub Template Repository** — click **Use this template** on GitHub to create your own copy, then follow the [setup steps](#setup) below.

Terraform + cloud-init repo for provisioning on-demand Kubernetes dev servers on Hetzner Cloud.
Triggered via GitHub Actions or the Backstage developer portal.

---

## Setup

Follow these steps after creating your repo from this template.

### 1. Enable template features on GitHub

Go to your repo **Settings → General** and confirm **Template repository** is checked (it is set on the source repo; verify it carried over).

### 2. Configure GitHub Secrets

Go to **Settings → Secrets and variables → Actions → Secrets** and add every secret below.

#### Infrastructure secrets

| Secret | Description |
|--------|-------------|
| `HCLOUD_TOKEN` | Hetzner Cloud API token (read/write) |
| `SSH_PUBLIC_KEY` | Ops SSH public key added to every server |
| `SSH_PRIVATE_KEY` | Corresponding private key (used by CI to snapshot provision logs) |
| `HZ_S3_ACCESS_KEY` | Hetzner Object Storage access key (Terraform state backend) |
| `HZ_S3_SECRET_KEY` | Hetzner Object Storage secret key |

#### State backend secrets

| Secret | Example value | Description |
|--------|---------------|-------------|
| `TF_STATE_BUCKET` | `my-terraform-state` | Object Storage bucket name for Terraform state |
| `TF_STATE_REGION` | `eu-central-1` | Region string passed to the S3-compatible backend |
| `TF_STATE_ENDPOINT` | `https://fsn1.your-objectstorage.com` | S3-compatible endpoint URL for your Object Storage |

#### Notification secrets (optional — only needed if using email notifications)

| Secret | Example value | Description |
|--------|---------------|-------------|
| `SENDGRID_API_KEY` | `SG.xxx` | SendGrid API key |
| `NOTIFY_FROM_EMAIL` | `devops@yourcompany.com` | From address for server-ready emails |
| `NOTIFY_FROM_NAME` | `Your Team DevOps` | Display name for notification emails |

### 3. Update the Backstage templates (optional)

If you use Backstage, edit [`backstage/template.yaml`](backstage/template.yaml) and replace the two placeholders with your own org and repo name:

```yaml
repoUrl: github.com?owner=YOUR_GITHUB_ORG&repo=YOUR_REPO_NAME
url: https://github.com/YOUR_GITHUB_ORG/YOUR_REPO_NAME/actions/workflows/...
```

Then register `backstage/template.yaml` in your Backstage catalog.

### 4. (Optional) Customise tool versions

Tool versions are pinned in [`cloud-init.yaml`](cloud-init.yaml) inside the `setup.sh` script. Edit the version variables at the top of that script to upgrade or pin different versions.

|------|---------|
| Docker | latest stable |
| kubectl | v1.30.0 |

| k9s | v0.32.5 |

| stern | v1.30.0 |
| yq | v4.44.2 |
| dive | v0.12.0 |

## Quickstart (local)

```bash
cp terraform.tfvars.example terraform.tfvars
# edit terraform.tfvars with your values

terraform init -backend-config=backend.hcl   # or use local backend for testing
terraform plan
terraform apply
```

## Via GitHub Actions

### Create
Go to **Actions → Create Hetzner Dev Server → Run workflow** and fill in the inputs.

### Destroy
Go to **Actions → Destroy Hetzner Dev Server → Run workflow**.
The `username`, `region`, and `server_name_prefix` inputs **must exactly match** what was used at creation — they determine the state file path.

---

## Via Backstage

Register `backstage/template.yaml` in your Backstage catalog.
Two templates are provided:
- **Create Hetzner Dev Server**
- **Destroy Hetzner Dev Server**

Both dispatch the corresponding GitHub Actions workflow.

---

## State backend

State is stored in Hetzner Object Storage (S3-compatible).
The state key pattern is:

```
hetzner-servers/{server_name_prefix}-{region}-{username}/terraform.tfstate
```

The backend is configured dynamically at `terraform init` time via `backend.hcl` (generated by the workflow — never committed).

## Architecture

```
├── .github/
│   ├── workflows/
│   │   ├── server-up.yaml          # Create workflow
│   │   └── server-down.yaml        # Destroy workflow

│   └── PULL_REQUEST_TEMPLATE.md    # PR checklist
├── backstage/
│   └── template.yaml               # Backstage scaffolder templates (create + destroy)
└── scripts/
    └── send-email.sh               # SendGrid email helper
```
